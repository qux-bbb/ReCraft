## 1. 多入口循环规范化（唯一能显著提升结构化率的方向）

> **2026-11-03 更新（已部分落地，结论先行）**：复核发现 notepad 15 个回退函数里 **12 个不是

> 另一侧分支被当成早退 → 幸存路径越过 join，把另一侧的 fallthrough 变成 `goto`」。
> 已实现 `may_post_dominators`（终止路径不施加约束的后支配集合）并用「干净菱形」做门
> （join 的每个前驱都无条件落入、join 在循环体内、两臂都未发射）后：notepad 5 个快照变短
> （`sub_140007924` −19 行、`sub_140007ab4` −17、`sub_140026438` −2、两个 mutex helper 各 −1），
> Go 结构化 **2,998 → 3,003（92.1%）**；crackme / corpus / corpus86 / go 快照零变化，
> lint 仍 0 findings。**更宽的 join 串联不要再试**（去掉"干净菱形"门）：它让 crackme 的
> `sub_1400030a8` 把同一段尾部复制 5 次、`sub_14000391c` 生成 `while (1)` 套 `goto`——这是
> emitter 对任意 join 不够健壮，不是分析本身的问题。其余回退（notepad 15 个、Go 258 个）
> 仍未消除，下面 §1.1/§1.2 的复现与实现路径继续有效。

**症状**：函数体内出现 `loc_…:` 标签 + `goto`，而不是 `while`/`do` 循环。

**共同原因**：循环有**两个入口**——正常入口在循环头，另一个入口是一条**向后**跳转落
在循环体中部（重试/清理点）。循环头因此不支配其回边，属于不可规约流图，规则式化简
拒绝处理并回退成标签 + `goto`。

**样本**：

| 样本 | 位置 | 保护方式 |
|---|---|---|
| notepad `sub_140004264` | 第 168 个函数 | `tests/golden/notepad`（170 个快照）+ lint |
| Go `internal/abi.Name.ReadVarint` | 第 51 个函数 | `tests/golden/go`（60 个快照）+ lint |

**量化（notepad 14/15 个回退函数，199 处向后跳转）**：其中 **161 处**的目标标签位于某个
`if`/`else` 分支内部（117 处集中在单个 45 KB 函数 `sub_140013154`），只有 38 处落在顶层。
即"守卫提升"要处理的正是这 161 处；单个大函数占了七成，说明该形状在超大函数里成簇出现，
可优先在那一处验证实现是否奏效（收益最集中）。**该函数内部的热点**：`sub_140013154` 有 215 个标签、76 个被向后跳转的目标；最热的三个
`loc_14001de8b`（16 次）、`loc_140017355`（15 次）、`loc_140015c81`（8 次）合计 39 次，
且每个标签的引用全部来自向后跳转（即纯粹的重试环）。**先让这三个成环**就能把该函数的
`goto` 减少四成，是成本最低的验证点。**最纯粹的一例**（`loc_140017355`，第 1238 行）：标签正好是一个 `if` 分支的**第一条语句**，
分支体只有一句 `r13d = 0xc0000095;`，而它被下方 15 处（当前输出第 7778–7874 行）向后跳回：

```c
if (rax < r12) {
    loc_140017355:        // 从 15 处跳回这里，跳过 if 判断
    r13d = 0xc0000095;
} else { … }
```

跳转落在分支内部、而分支在跳转点之前就结束了 → 区域不闭合，文本层无法折叠；这正是
"守卫提升 / 节点复制"要解决的形态。实现时可用这一处做最小复现（分支体仅一句，便于对照）。

**预期收益**：notepad 现有 452 处 `goto loc_`，其中 161 处是"跳进 if 分支"的向后跳（本次要处理的目标）。
若全部成环并让标签随之被 `tidy_labels` 删除，`goto` 至少可降到约 **291** 处（−36%），
`loc_` 标签 267 → 约 106；结构化函数数预计从 487/502 继续上升（具体幅度取决于每个函数是否只剩这一处回退）。

不是样本挑选造成的。

## 1.2 第二种多入口形状：`goto` 跳进紧邻的 `do` 体内（Go 样本）

Go 的 `internal/abi.Name.ReadVarint`（0x140001ba0，8 块、2 处 goto）展示了另一种形态：

```c
if (rsp > *(u64*)((r14 + 0x10))) {
    … 两条赋值 …
    goto loc_140001bd3;        // 跳过 do 体开头的两条语句
    do {
        rcx = (rdx + 1);
        rdx = rbx;
        loc_140001bd3:         // ← 这里被上面的 goto 命中
        …循环体…
    } while (…);
```

**可用的解法是"循环复制"（node splitting 的文本版）**，且比守卫提升更机械：

1. 识别 `goto loc_X;` 紧跟 `do {`，且 `loc_X:` 位于该 `do` 体内（首个语句之后）；
2. 取 `do {` 开头到 `loc_X:` 之前的语句段 P（此例仅 2 条）；
3. 在 goto 处复制 P + `loc_X:` 起的整个循环体 + 同一 `while` 条件，形成一个独立 `do … while`；
4. 若 P 或复制体超过阈值（例如 40 行）则放弃，保持现状。

**规模实测（决定优先级）**：notepad 全量 502 个函数中，这种「`goto` 紧邻 `do` 且跳进其体内」的形状
只有 **1 处**（`0x0140007570` 的第 88 行），Go 侧目前见到的也只有参考函数那一处。相比之下，§1 的
"向后跳进 `if` 分支"有 **161 处**。因此：**先做 §1（守卫提升），这条只作为长尾收尾**，
不要为它单独设计通用机制。**风险与验收**：`break`/`continue` 在复制体内语义不变；复制只发生在 goto 路径（原本就跳过 P）。
验收仍是 lint（括号/标签/参数）→ golden diff（每处变化都能解释为"复制了一段循环"）→ metrics
（`goto` 数下降）。notepad 侧应先用 `--list` 找出类似形状再实施。

## 2. 次要候选（收益小、风险低）

- 已完成：嵌套单臂 `if` 折叠为 `&&`（`collapse_nested_if_wrappers`，notepad −143 行）。同类候选
  还有"`else` 分支只有一句时改写成前置守卫"和"`if (a) { return x; } return y;` 折叠为三元"，
  都属安全的纯文本改写。

- `__asm` 剩余 138 行：原子指令（`lock xadd`/`lock cmpxchg`/`xchg`）、单操作数
  `imul`/`mul`、间接 `jmp`、未建模标志的分支。前者可在 lifter 层展开为三条语句，
  后者需要更完整的标志建模。
- lint 并行化：`Session` 是 `&mut`（渲染需要 lift 指令），需要先把渲染改成只读快照
  才能按函数并行；当前 Go 全量 L1 自检约 9 分钟。
- 伪 C 中 Go/C++ 符号名（`go:buildid`、`internal/abi.Name.ReadVarint`）不是合法 C 标识符，
  为便于与符号表对照而保留原样；若要合法化，需在渲染层做标识符清洗并同步 golden。

## 2.1 已排查、不必做的方向

- **跳到下一行的 `goto`**（`goto loc_X;` 紧跟 `loc_X:`）：全样本实测 **0 处**，发射器不会产生
  这种形状，写 `drop_fallthrough_gotos` 是白做。
 **把 `goto` 改写成 `continue`/`break`**：notepad 452 处 `goto` 中，目标是"所包围循环的第一条
  语句"（等价 `continue`）的有 **0 处**，目标是"循环结束后的第一条语句"（等价 `break`）的只有
  **4 处**。发射器本来就用 `break`/`continue` 表达这类流，剩下的都是跨层跳转，改写没有收益。- 同理，"`goto` 指向紧跟外层 `}` 之后的第一条语句"这类退化跳转已由 `fold_jumps_over_braces`
  覆盖，无需另加 pass。 **在文本层折叠"同层"回跳**：notepad 所有向后 `goto` 的源与目标**都不在同一个块内**
  （intra-block 命中 **0**），即每一处回跳都至少跨出一个 `{}`。这从数据上说明文本层已经做到头，
  剩下的必须由结构器改 CFG——不要再尝试新的文本 pass 去消灭这些 `goto`。

## 3. 不要做的事

- 不要为了"看起来像 C"而删除或合并语义不明的分支（尤其 `if (0x80004005 >= 0)` 这类
  常量条件，它可能暴露的是我们常量归属推断的边界）。
- 不要在未跑 `recraft-cli lint` 的情况下提交文本 pass 改动——它能立刻发现未定义标签、
  括号失衡、参数未声明等硬错误。
