## 2. 算法

1. **CFG**：复用 `build_cfg`（基本块 + fallthrough/taken/not-taken/jump/table 边）。
2. **支配树**：RPO 上迭代计算 immediate dominator（Cooper-Harvey-Kennedy）。
3. **后支配树**：加入虚拟出口节点，反向图上迭代；`ipdom(header)` 即 if/else 的汇合点。
4. **自然循环**：回边 = 目标支配源；循环体 = header ∪ 不经过 header 能到达回边源的块；嵌套循环取最内层。
5. **发射**：
   - if/else 菱形：`if (cond) { then } else { else }`；某一臂为空时退化为 `if`/`if (!cond)`。
   - 无汇合（两臂都 return）：`if (cond) { ... return; }` + 顺序发射 fallthrough（早退风格）。
   - 循环：`while (1) { header stmts; if (cond) break; body }`，避免 header 语句被错误地只执行一次。
   - 跳表：`switch (selector)` 按表项顺序生成 `case N: goto loc_xxx;`；selector 从索引寄存器的 `mov dst, src` 回溯（L2 下若仍是入参则显示 `argN`）。
   - 其余（不可归约、间接跳转）→ `if (...) goto loc_x;`，最终补全未访问块。

## 3. 输出示例

`branchy`：

```c
void branchy_l1(void) {
    edx = ecx;
    if ((ecx <= 0xa /* signed */)) {
        ecx = -(ecx);
        eax = (eax ^ eax);
        __asm("cmovl eax, ecx");
        return;
    }
    eax = (rcx + (rcx * 1));
    return;
}
```

`loopy` 会生成 `while (1) { ...; if ((eax >= r9d)) break; }`。

`switcher_big` 的 20 路跳表（selector 已回溯）：

```c
/* jump table: 20 targets, selector=arg1 */
switch (arg1) {
    case 0: goto loc_14000145f;
    case 1: goto loc_140001465;
    ...
}
```

## 4. L2 变量与签名

- **入参寄存器（x64）**：Windows x64 fastcall 的 `rcx/rdx/r8/r9`，按"读先于写"判定是否真的作为参数使用；写入后不再当作参数，签名按固定顺序生成 `int64 arg1, int64 arg2...`。
- **栈参数（x86）**：有帧指针（`push ebp; mov ebp, esp`）时 `[ebp+8]`、`[ebp+0xc]`…… → `arg1..`；无帧时 `[esp+4]`、`[esp+8]`…… → `arg1..`。一旦出现 `push`/`sub esp` 导致 esp 移动，esp 相对参数推断保守放弃（避免把局部变量误标成参数）。
- **栈槽命名**：`*(u64*)((rsp + 0x28))` → `var_28`（负偏移 `var_n8`），读写都替换，宽度暂不体现在名字里。对 `[ebp+正偏移]` 的**写**不套用参数名（避免看起来像给参数重新赋值）。
- **写目标**：写寄存器始终用具体视图名（`ecx = ...`），只有对仍是入参值的**读**才显示 `argN`，避免把参数名当成可重新赋值的变量。
- **SSA-lite 覆盖追踪（本批）**：对 CFG 做 may-write 前向数据流（函数入口为空集，`in[b] = ∪ out[pred]`），再按块的入口集合重新提升；只有在所有路径上都未被覆盖的入参读取才保留 `argN`，join 处的已覆盖值退回具体寄存器视图。真正的 SSA/phi 与变量重命名留到下一批。
- **返回类型（本批）**：按函数体内对 `rax/eax` 的写宽度推断 `int64`/`int32`；没有写但存在调用或尾调用（值直接透传）→ `int64`；两者都没有 → `void`。
- **调用约定（本批）**：x64 固定 MS ABI（签名无关键字）；x86 看函数最后一条指令——`ret imm16` → `__stdcall`，`ret` → `__cdecl`。corpus 新增 `__stdcall` 探针函数，x86 下与 cdecl 工厂函数区分验证。
- **接入**：`decompile --l2`；UI 伪代码页签新增 "L2 (vars)" 复选框（自动开启 L1）。

`add_leaf` 输出（x64）：

```c
// L2 params: arg1=rcx, arg2=rdx
int32 add_leaf(int64 arg1, int64 arg2) {
    eax = (arg1 + (arg2 * 1));
    return;
}
```

x86 stdcall 探针：

```c
int32 __stdcall stdcall_add(int64 arg1, int64 arg2) {
    eax = arg1;
    eax = (eax + arg2);
    return;
}
```

## 7. 基础类型（第一批）

- **浮点标量**：`movss/movsd` 及 `addss/…/divsd` 的内存操作数现在是 `Expr::LoadFloat` /
  `Stmt::StoreFloat`（宽度 4/8），打印为 `*(f32*)` / `*(f64*)`；浮点运算使用
  `BinOp::FAdd/FSub/FMul/FDiv`（同一组 C 运算符，另有 `is_float()` 供后续类型推断使用）。
  `cvttss2si` / `cvtsi2ss` 双向转换按源操作数类型选择整数/浮点加载。
- **SSE 向量**：16 字节读写打印为 `__m128`；整包运算（`paddd` 等）仍按标量运算符展示
  lane-wise 语义。
- **签名类型**：返回类型 `void/int32/int64`（上一批）；参数按使用方式推断——作为内存基址且
  访问宽度唯一时给出指针类型：1 字节 → `char*`、2 字节 → `wchar_t*`、4/8 字节 →
  `int32*`/`int64*`，宽度混合 → `void*`，未作基址 → `int64`（本批，仅 x64 寄存器参数；
  x86 栈参数暂保持 `int64`）。
- **字段访问**（本批）：指针类型参数以常量偏移解引用时打印为 `arg1->field_XX`
  （负偏移 `field_nXX`），覆盖整数与浮点读写；示例 corpus `field_probe`：
  `int32 field_probe(int32* arg1)` → `eax = arg1->field_10;`。这是 DESIGN 允许的
  `field_XX` 风格，尚无结构体布局/类型传播。
- **用户原型覆盖（本批升级）**：`recraft prototype <project> --addr <func> --text "int
  __stdcall foo(const char* text, int count)"` 把 C 声明写入 `prototype` 表（schema v2，
  Command 总线 + undo/redo），伪代码首行显示 `// prototype: ...`。**声明会被解析**：
  返回类型、调用约定、参数类型与参数名覆盖推断结果并驱动签名（x64 最多 4 个寄存器参数；
  x86 按栈偏移顺序映射到 `[esp+N]`/`[ebp+N]` 参数槽），例如 x86：
  `int32 __stdcall stdcall_add(int32 a, int32 b)`，正文用 `a`/`b` 代替 `arg1`/`arg2`。
  `recraft unprototype` 删除；不支持嵌套声明（函数指针）与数组参数。
- **用户结构体布局（apply_type，本批）**：`recraft define-struct --name Probe --size 24
  --field 0:tag:u32 --field 16:value:i32` 定义布局（schema v3：
  `user_struct`/`user_struct_field`/`func_arg_type`），`recraft apply-type --addr <func>
  --slot 0 --type Probe` 绑定到参数槽，反编译把 `arg1->field_10` 渲染为
  `arg1->value`；`recraft structs` 列出布局，`--type` 省略即清除绑定，全部经 Command
  总线 journal/undo/redo；AI `apply_type` proposal（value `"<slot>:<Type>"`）走同一路径。
  字段宽度/嵌套结构/跨函数传播未做。
- **数组下标（本批）**：带缩放的寻址（`[rcx+rax*4]`、`[rcx+rax<<2]`、`char*` 的字节
  偏移）在指针类型参数上渲染为 `arg1[index]`；索引寄存器若被 `movsxd` 等改写则显示
  实际寄存器名。示例 corpus `array_probe`：`eax = arg1[rax];`。无类型缩放信息时回退
  指针算术。
- 示例（corpus `float_math`）：

```c
int32 float_math(void) {
    xmm0 = (xmm0 * *(f32*)(0x140002044));
    xmm0 = (xmm0 + *(f32*)(0x140002040));
    eax = (int32*)(xmm0);
    return;
}
```

## 8. 已知限制
- **switch selector** 只回溯简单 `mov dst, src` 链；经过算术变换（如 `sub eax, 3`、`and eax, 0xf`）的索引会退回寄存器原名或占位 `index`，case 体目前仍是标签块而不是内联语句。
- 循环 header 中条件之前的语句按"每次迭代"处理，但与真实语义可能仍有偏差（当前把 header 语句放进循环体，已比"只执行一次"更接近）。
- **L2 仍是近似**：已做 may-write 跨块覆盖追踪（SSA-lite），但还没有真正的 SSA/phi 与变量重命名；类型覆盖浮点标量、`__m128` 与 x64 指针参数，整数宽度/x86 栈参数/结构体/数组/跨函数类型传播仍未做。
- **x86 参数**：`push`/`sub esp` 之后的 esp 相对访问不当作参数（保守回退 `var_XX`）；`[ebp+偏移]` 自动推断默认 `int64`，仅用户原型（函数级）可覆盖名称与类型；`fastcall`/`thiscall` 的寄存器参数未处理。
- **返回类型/ABI 是启发式**：`int32/int64/void` 仅看 `rax/eax` 写宽度与调用/尾调用；`__stdcall` 仅由 `ret imm16` 识别（`__fastcall`/`__thiscall` 与可变参数函数不做特判）；装饰名（如 `_stdcall_add@8`）暂未优先选择无修饰别名。
- **结构器（本批增强）**：`test`/`cmp` 后的有符号条件跳转现在可建模（`test a,b` 的
  SF/ZF 语义，`jle/jg/jl/jge` 及对应 `cmov`），早退链（多目标跳到返回块）与"守卫条件 +
  循环"形态可正常结构化；if 臂的 join 落在外层区域 stop 集合内时不再回退 goto，空臂不再
  生成空 `if`；循环体内跳到循环出口/header 的分支分别输出 `break;`/`continue;`；
  **单块循环（header 即 latch）识别为 `do { ... } while (cond);`**；**jump-table 的
  leaf case（`return` 或跳到 switch join）内联为 `case N: { ... }`**，其余复杂 case 仍保留
  标签/goto 形式。notepad 结构化率 **49.2% → 62.4% → 77.3% → 77.7%**（502 函数，超过
  70% v1 目标）。
- 不可归约 CFG 一律回退 goto；含共享/复杂 case 体的 switch 仍用标签块。
