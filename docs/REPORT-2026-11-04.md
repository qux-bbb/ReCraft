## 1. `rbp` 只有被证明是帧基址时才当作帧（`fix(decompile)`，commit `26e18a8`）

**发现的错误**：`stack_reference` 把"本函数写过 `rbp`"当成"重建了帧"。于是把 `rbp`
当普通指针用的函数（`rbp = arg1`、`rbp = [rax + 8]`）里，结构字段访问被误标成栈槽：

| 反汇编 | 旧输出 | 新输出 |
|---|---|---|
| `test dword ptr [rbp+0x18], 0x100`（`rbp = [rax+8]`） | `var_18 & 0x100`（与真正的 `[rsp+0x18]` 同槽） | `*(u32*)((rbp + 0x18))` |
| `lea edx, [rbp-0x80]`（`ebp = 0` 时的整数运算） | `&var_n80`（不存在的槽地址） | `(rbp - 0x80)` |
| `inc rbp` / `add rbp, 0x50` | `rbp = &var_1` / `rbp = &var_50` | `rbp += 1` / `rbp += 0x50` |

**修法**：只有 `frame_reg`（`mov rbp, rsp` 的帧别名）或 `pointer_offsets`（`lea` 自栈地址
得到的位移）成立时才命名槽；未被写过的 `rbp` 仍按调用方槽命名（x86 栈参数在它上方）。

**影响**：notepad 7 个、crackme 2 个快照变化，逐条核对都是上面三类误标；crackme `loc_`
标签 218 → 216；metrics 其余不变。

## 2. 常量折叠扩展（`feat(decompile)`，commit `740eff8` + `87e4b8d`）

`fold_constant_registers` 原来只把常量折进 32/16/8 位拼写，且只看"第一个提及"。三处扩展：

1. **32 位写零扩展进 64 位父寄存器**：`r9d = 0; … (r9 + 2)`、`var_38 &= rbx`（`ebx = 0`）
   都能折叠；负数字面量排除（`eax = -1` 留下的是 `0xffffffff`，不是 `-1`）。
2. **扫描改成"第一个能接受常量的读"**：遇写即停，跳过不可折的读（`r9d = (rax - 5)`），
   因此中间夹一条读不再让后面的比较失去机会。
3. **死写判断按寄存器族扫**：只有"任何拼写被读之前先被完整覆盖"才删赋值。旧实现只看
   32 位名字，会在后面还有 `r15`/`rax` 读取时删掉赋值——**这是真实的错误删码**，
   输出里会留下未定义的寄存器读（`if (rdx > rax)` 而 `rax` 从未赋值）。
4. **常量经寄存器写出的存储**：`esi = 0x78; var_20 = esi` → `var_20 = 0x78`、
   `rax = -1; qword_X = rax` → `qword_X = -1`、`eax = 0; rbx = rax` → `rbx = 0`。
   只在写本身是 32/64 位时折叠：窄写（`var_20 = dil`）保留宽度线索，
   `xmm0 = 0; xmmword_X = xmm0` 保留整块清零的形状。
5. **比较折叠的门收紧到"比较自身"**：`/* signed */` 只是注释，不再把
   `if (eax >= 0)` 误判成"还有其他操作数"，因此不再制造 `if (0x20 >= 0)` 这类常量条件
   （旧实现靠注释里的 `signed` 通过了 `has_identifier` 检查）。

**效果（notepad 全量 L2）**：**29 626 → 29 428 行（−198）**；502 个函数里 100 个变短；
`goto` 450、结构化 487/502（97.0%）、覆盖率 99.6%、标签 265、`__asm` 134 全部不变。
crackme 453/493（91.9%）、标签 216、`__asm` 265 不变。corpus / corpus86 / Go 只有零散同类折叠。

## 3. 派发阶梯重建成 `switch`（`feat(decompile)`，commit `HEAD`）

**问题**：编译器把稀疏 `switch` 降成 `sub`/`je` 阶梯——每一层从选择子寄存器里减去下一个
case 值、再测余数是否为零，寄存器里是**累计余数**。发射器如实输出成每层一个 `if`，于是
`sub_140023f90`（对话框消息处理）达到 **11 层缩进**，`sub_140010f48`、`sub_14000f1d0` 等
同类函数也一样，dispatch 结构完全看不出来。

**修法**（`fold_dispatch_ladders`，文本层）：识别同一寄存器的 `reg -= c; if (reg == 0) {`
阶梯，重建为 `switch (reg)`：

- case 值 = 累计减法之和（`ebx -= 2` → `case 0x2`，再 `-= 0xe` → `case 0x10`，……）；
- 三种结尾都支持：`} else { 默认 }`、`} else if (reg != K) { 默认 }` + 尾部"最后一个 case"、
  `} else if (reg == K) { 最后一个 case }`（无默认）；
- **展平的阶梯**也识别：上一臂以 `goto` 结束、发射器把下一层写成后续语句（不是 `else` 臂）时，
  只要下一层是同寄存器的 `reg -= c; if (reg == 0) {` 就接着解析；
- **只有 case 体或 switch 之后的代码还读该寄存器时**，才在每个 case 开头补回
  `reg -= <累计>;`（余数语义与阶梯完全一致；无默认的阶梯还会补一个只做减法的 `default`，
  保证"没有匹配"的路径也留下同样的余数），否则输出保持干净；
- 含顶层 `break;` 的 case 体不转换（`break` 会改绑到 `switch`），`continue`/`return`/`goto`
  语义不变；default 臂后面还挂着 `else if` 的长链也不转换——尾部语句不属于单一 case
  （kernel32 `sub_180036084` 就是这种形状，早期版本在这里漏了一个 `}`，靠 kernel32 的
  `lint` 抓到，现已加门并补了回归单测）；
- case 体按层级整体重新缩进（阶梯每层多缩进 4 格，直接搬过来会错位）。

**效果**：notepad **14 个函数**（其中 5 个来自展平阶梯）、crackme 全样本 **4 个函数**
（160 份快照范围内 2 个）从嵌套 `if` 变成 `switch`（`sub_140023f90` 的 11 层变 1 层）。
L2 行数 **29 428 → 29 533（+105）**——`case`/`break`/`}` 比嵌套 `if` 多行，这是刻意的取舍：
结构可读性远比行数重要（见 `REPORT-2026-11-02.md` 里"行数不值得追求"的结论）。`goto` 450、
结构化 487/502、标签 265、`__asm` 134 均不变；crackme 与 corpus / corpus86 / Go 的数字也不变。
lint 五个样本 0 findings、785 份快照全过，另外**抽查 kernel32（2 567 函数 / 5 134 份文本）
0 findings**——正是它发现了上面的漏括号。

## 4. 空 `else` 与 `void` 尾部 `return;`（`feat(decompile)`）

两个小的"去噪"清理：

- **空 `else` 臂**：`if (c) { … } else { }` 直接闭合 if（少一级缩进、语义相同）。notepad 里
  只剩 1 处（`sub_140004cb4`），说明这类残留在发射器里已经很少。
- **`void` 函数末尾的 `return;`**：notepad 有 **89** 个 `void` 函数以 `return;` 结尾，这行是
  隐式尾声，其它反编译器都不打。只在 **L2** 视图里省掉（L1 是"原始结构"视图，保留显式尾声，
  这样 785 份快照基线里 639 份不受影响）；另外 4 个非 `void` 函数仍保留。
- 两处合计 **−90 行**（29 533 → 29 443），只动 1 份快照。

## 5. 复合赋值（`feat(decompile)`）

发射器把"读—改—写"印成 `x = (x | 4);`，而源码里是 `x |= 4;`：同一行里左边的地址写了
两遍。`fold_compound_assignments` 原本只认标识符左侧（寄存器/槽/全局），本轮扩到**内存位置**
（`*(u64*)(rax)`、`arg1->field_0`）：左侧文本必须与右侧被读的那个位置完全一致，且右侧不能
含调用——否则地址会被多求值一次（寄存器/槽没有这个问题，所以老路径不加这条门）。
`|`/`&`/`^`/`+`/`-`/`*`/`/`/`<<`/`>>` 都支持，`x = (x + -0x30)` 折成 `x -= 0x30`，
`x = (x | -1)` 折成 `x = -1`。

**效果**：notepad 新增 **64 处**复合赋值（24 个函数），crackme 160 份快照里 **26 个函数**，
L2 行数 29 443 → **29 442**（行数几乎不变，但每行短了一半，`*(u64*)(rax) = (*(u64*)(rax) |
4);` → `*(u64*)(rax) |= 4;`）。`goto`/结构化/标签/`__asm` 全部不变。

## 7. 新发现、但本轮未做的

- **调用实参里的 `rbp` 相对读仍可能不带归一化槽名**：实参文本由*未播种*的第一遍 lift 渲染
  （那一遍没有帧位移），所以 `sub_1400225a4`、`sub_1400229e8` 里几个实参退化成
  `*(u64*)((rbp + 0x6f))`（忠实但不如 `var_128` 可读）。要修需要让实参值在带 `stack`/
  `frame_pointer` 的第二遍里重渲染，属于数据流层改造。
- **派发阶梯还有长尾**：notepad 转换了 14 个（含展平阶梯）；剩余未转换的多半含顶层
  `break`（会改绑到 `switch`）、default 臂后还有 `else if` 长链，或形状不规整，按设计保留。
- **快照不覆盖常量**：`normalise_line` 把所有十六进制字面量换成 `0xADDR`（为跨 MSVC 版本
  保持形状稳定），所以常量折叠、`case` 值这类"数字"改动只能靠人工 review；本轮已用脚本
  逐条核对 **18 个** switch（notepad 14 + crackme 4）的 case 值与阶梯累计和，并手工核对了
  `sub_140006300` 的反汇编。
- **死槽写（下一步候选，已量化）**：notepad L2 有 **496** 处 `var_XX = …;` 在整个函数里再没
  被读到过，占 1.7% 的行。但大多数是"逐字段写、再把 `&var_140` 交给 API"的结构体初始化，
  删掉会改语义；只有**函数里完全没有 `&var_`**（没取过局部地址）时才能安全判定，这个子集
  只有 **53** 处（26 个函数）。做成通用 pass 需要"地址被取走的区间"这层别名分析。
- **循环旋转/`for` 恢复：文本层无解（已量化）**：notepad 里 `while` 只有 83 个、`do { … }
  while (…)` 有 194 个——发射器输出的是底测循环。把 `do { B; i += 1 } while (i < n)` 还原成
  `for (i = …; i < n; i += 1)` 需要在前面补一次条件判断，而"`if (C) { do { … } while (C); }`"
  这种理想旋转形状在 notepad 里只有 6 个、条件文本完全相同的 **0** 个（编译器做了强度削减，
  前置判断与闩锁条件不是同一个表达式）。`while` 形式里"末句是自增、条件用同一变量"的候选
  也只有 **3** 个。要真正还原 `for` 得在 CFG/SSA 层做归纳变量分析，不是文本层能做的。
- 多入口循环 / 共享错误尾仍是既有结论（文本层无解，见 `docs/NEXT.md` §1）。
