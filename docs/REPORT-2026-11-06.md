# 2026-11-06 进展：把 crackme 的 `main` 还原成源码形状

目标是"以 `crackme_win_x64.exe` 为例，把它的 `main` 向源码努力，且优化要有普适性"。
这一轮围绕四条线推进——**结构**、**表达式**、**局部变量**、**函数名**——每一处改动都放在
五套样本（crackme 495、notepad 506、corpus 31、corpus86 32、go 3261 个函数）上验证。

## 1. 结果：`main` 与源码等价

挑战自带源码（`ctf-simple-crackme/src/crackme.c`），可以逐句对照。下表的"反编译"一列是
`decompile --l2` 的真实输出（套上 `scripts/case-crackme.ps1` 的原型表）。

| 源码 | 反编译 |
|---|---|
| `int main(void)` | `int32 main(void)` |
| `char buf[256];` | `uint8 var_20` 栈槽（`&var_20`） |
| `puts("====")` ×4 | `puts((char*)"====")` ×4 |
| `printf("Enter flag: ");` | `printf((char*)"Enter flag: ");` |
| `fflush(stdout);` | `v3 = __acrt_iob_func(1); fflush((void*)v3);` |
| `fgets(buf, sizeof(buf), stdin) == NULL` → `break` | `v6 = fgets((char*)&var_20, 0x100, (void*)v5); if (v6 == 0) { …hint…; return 1; }` |
| `nl = strpbrk(buf, "\r\n"); if (nl) *nl = '\0';` | `v7 = strpbrk((char*)&var_20, (char*)"\r\n"); if (v7 != 0) { *(u8*)(v7) = 0; }` |
| `strcmp(buf, legacy_flag) == 0` | `v8 = strcmp((char*)&var_20, (char*)"flag{…}")` |
| `strlen(cand) != FLAG_LEN` | `v9 = strlen((char*)&var_20); if (v9 == 0x20)` |
| `v = cand[perm[i]] ^ key_str[i % KEY_LEN];` | `v13 = *(u8*)(&var_20 + v11); v13 ^= byte_140018368[v12];` |
| `v = (unsigned char)(v + perm[i]);` | `v13 += (uint8)v11;` |
| `if (v != enc[i]) return 0;` | `if (v13 != byte_1400183a0[v10]) goto loc_140001130;` |
| `for (tries = 0; tries < 3; tries++)` | `v1 = 0; do { … v1 += 1; } while ((int32)v1 < 3);` |
| `puts("[+] Correct! …"); return 0;` | `puts((char*)"[+] Correct! …"); return 0;` |
| `puts("[?] Hint: …"); return 1;` | `puts((char*)"[?] Hint: …"); return 1;` |

差异只剩三类，都不是反编译器的判断错误：

1. **`break` 被编译器尾复制**：源码 `if (fgets(…) == NULL) break;` 在二进制里变成
   "分支里再放一份循环后的 `puts(hint); return 1;`"，我们照实输出。
2. **`strcmp` 条件被反转**：源码 `if (strcmp(…) == 0) { puts(wrong); continue; }` 在二进制里
   是"不等则走验证"，我们输出 `if (v8 != 0) { … }`，语义相同。
3. **`verify()` 被内联**（`-O2`），所以验证循环出现在 `main` 里。

## 2. 关键改动

### 2.1 结构

- **平坦回退补齐 fallthrough 边**（`665cad5`）：平坦区域里"落空"的块以前会丢边，导致
  `main` 在输入耗尽时打印 "Correct!"；现在下一块不是 `not_taken` 就补 `goto loc_…`。
- **常量折叠的支配性修复**（`a5e6489`）：上一轮放开的"最后一次写可折进嵌套块"漏了
  "定义所在块已闭合"的检查，`if (rax == 0) { eax = 1; return; }` 之后的 `*(u8*)(rax) = 0;`
  被折成 `*(u8*)(1) = 0;`（notepad 的 `sub_140010798` 甚至丢掉整段 `if`）。现在扫描在
  深度低于定义、或同层遇到 `return`/`goto`/`break`/`continue` 时截止，并加了回归测试。

### 2.2 表达式与地址

- **常量基址折进地址**（`870a834`）：`*(u8*)((i + 0x140018380))` → `byte_140018380[i]`，
  字符串/数组下标因此可读。
- **变参调用按格式串确定实参个数**（`6dc6f88`）：`printf("Enter flag: ", rdx, r8, r9)` →
  `printf("Enter flag: ")`；变参被调用者真正消费的实参个数由 `%` 转换符决定。

### 2.3 局部变量

- **按读取宽度声明**（`613bbcd`）：声明宽度取"最宽的一次读取"，`uint64 v` 不再满天飞。
- **变参实参不再算作被调用者的参数**（`42b01c8`）：`main` 的签名从
  `(int64 arg1, arg2, arg3, arg4)` 变成 `(void)`，与源码 `int main(void)` 一致。
- **常量实参准备语句清理**（`1845e6b`、`b47a28a`）：`ecx = 0; call(0)` → `call(0)`，
  L2 里对应的 `v4 = 0;` 与声明一并删除。
- **复制+自更新折叠**（`bbf21b5`）：`v12 = v10; v12 = (uint32)((uint32)v12 & 0xf);` →
  `v12 = (uint32)((uint32)v10 & 0xf);`。
- **`/* signed */` 注记清理**（`1f28be0`）：操作数已带 `(int32)` 时注记是重复，
  crackme 的 L2 注记 191 → 69。

### 2.4 函数名（静态 CRT）

`617f6b8`、`5094b89`：**不写回项目**，只在渲染层替换，函数头用 `// inferred: sub_… = name`
说明来源。证据规则：

| 名字 | 证据 |
|---|---|
| `printf`/`wprintf` | 被调用者入口把四个实参寄存器存进 home area（变参）+ 每个调用点首参是字符串字面量（宽字面量 → `wprintf`） |
| `strlen` | 无 call + 含 `0x7efefefefefefeff` + 入口只读 rcx |
| `strcmp` | 无 call + 含 `0x8080808080808080` + 入口读 rcx/rdx + `sbb`（-1/0/1 无分支返回）；`memcmp` 读第三个实参被排除 |
| `fgets` | 三入参 + 字节写入 + `0x16`(EINVAL) 与 `0xa`(换行) + **返回第一个实参**；跟进链接 thunk（`jmp` 到真实实现，最多两层） |

误判验证：四套样本 1064 个函数里只命名 3 个被调用者 + 1 个变参函数。开发过程中
`_read`（三入参 + 字节写 + `0x16`）曾被误判成 `fgets`，"返回第一个实参"这条把它排除了。

`de271e1` 修了命名路径上的一个真 bug：原型里的 `...` 被当成一个参数，导致
`printf((char*)"Enter flag: ", v3)` 多出实参，并把 `rdx` 拉进变量流、把验证循环展开成
一整行掩码表达式。

## 4. 剩余

`main` 里还有 4 个 CRT 调用名靠用户原型：`puts`、`__acrt_iob_func`、`fflush`、`strpbrk`。

它们不是"没做"，而是**没有可靠的结构证据**：`puts` 的换行在更深的 `_fwrite` 里；
`__acrt_iob_func` 的"下标 × 0x58 + 全局表"与任何"按下标取结构体"的函数同形；
`strpbrk` 是 70 块的 SSE 扫描，与 `strchr`/`strstr` 同形。IDA 靠 FLIRT 签名库解决这一类，
本仓库的对应机制是 `prototype`/`rename`（`scripts/case-crackme.ps1` 里就是这张表）。

更大的结构缺口是**多入口循环**（不可规约流图），与 `main` 无关：crackme 40 个未结构化
函数、notepad 19、Go 263。实现地图见 `docs/NEXT.md`。
