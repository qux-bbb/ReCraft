# M0 实施计划（走通骨架）

> 目标：8 周内（3 天/周 ≈ 24 个工作日）打通"打开 PE → 看反汇编 → 看 L0 伪代码 →
> 改名/注释 → 存盘 → 重开还在"的端到端链路，并完成 egui spike 裁决。
>
> 退出标准（DESIGN §14）：
> 1. 能打开真实 PE，看到指令与 L0 伪代码；
> 2. 改名/注释后关闭重开仍然存在（journal 生效）；
> 3. egui spike 五条验收达标（或触发 Tauri 回退决策）。

## 1. 交付物定义（Definition of Done）

### T2 `recraft-common`
- `Address(u64)`、`AddressRange`（半开区间）、`FuncId`/`TypeId` newtype。
- 统一 `Error`（thiserror：IO/格式/存储/取消/内部），带上下文。
- 单元测试覆盖区间运算、显示格式。

### T3 `recraft-storage`
- `Project::create/open/save`，single-file SQLite，WAL + 参数按 DESIGN §3.1。
- schema v1 迁移（`meta` 表存版本号），后续迁移脚本化。
- 镜像导入：256 KiB 分块、进度回调、可取消；`meta` 记录原文件 hash。
- `journal` 追加/回放/截断（checkpoint）。
- 测试：临时目录里 create → 写 1 MB 随机镜像 → 重开校验 → 取消导入后状态一致。

### T4 `recraft-format`
- `Loader` trait + `PeLoader`；`LoadedImage { segments, entry, imports, exports, tls, pdata }`。
- 容错：截断/重叠节/越界 RVA/超大 count 全部返回错误或降级，不 panic。
- 单元测试用手工构造的最小 PE 字节（测试内生成，不提交二进制）。
- 分析器种子输出：entry、TLS callbacks、`.pdata` 函数区间、导入 thunk 地址。

### T5 `recraft-decode`
- `decode_one(bytes, addr, mode) -> Result<Insn>`；`Insn` 按 DESIGN §5。
- `FlowKind` 判定（含 `jcc` 条件、间接跳转、`ret`/`int3`/`ud2`）。
- 解码缓存 API（先只做接口 + 简单 LRU）。
- 测试：指令长度/操作数对照 iced 基准；非法字节不 panic。

### T6 `recraft-core`
- `Session::open(pe_bytes) -> Session`：加载 → 建段 → 建 flags 页 → 应用 journal。
- 命令：`Rename`、`SetComment`、`SetCodeData`、`Undo`、`Redo`（其余 M1 加）。
- 读 API：`disasm_range`、`names_in`、`xrefs_to`（M0 可为空实现但接口定型）。
- 测试：1000 条随机命令 + 全撤销 = 初始状态；崩溃点（kill 前 flush）后重开 journal 一致。

### T7 `recraft-ir`
- LIR 节点：`Assign/Store/Load/BinOp/UnOp/Cmp/Branch/Call/Ret/Temp`。
- x86/x64 提升子集：`mov/lea/push/pop/add/sub/and/or/xor/cmp/test/inc/dec/jmp/jcc/call/ret/nop/xor reg,reg`。
- lazy flags：`cmp/test` 条件化，`jcc/cmov/setcc` 使用点求值。
- 测试：每个助记符的手工语义用例；未支持指令生成 `Intrinsic` 保留原文。

### T8 `recraft-cli`
- `recraft info <pe> [--json]`：段/入口/导入/导出/TLS/`.pdata` 数量。
- `recraft disasm <pe> --addr 0x... --count 20 [--json]`。
- `recraft decompile-l0 <pe> --func 0x... [--json]`：直线块 C 风格输出（L0）。
- `recraft strings <pe>`（最小实现：ASCII + UTF-16）。
- CI 可直接用 CLI 做 smoke test。

### T9 `recraft-ui`
- eframe + egui_dock；打开文件对话框（`rfd`）；拖放打开。
- 反汇编网格：虚拟化、token 着色、命中、选择复制、Goto（`G`）、Esc 返回历史。
- 内联改名（`N`）与注释（`;`），走命令总线。
- 伪代码面板：L0 文本 + `0x...` 到反汇编的跳转（先做行级）。
- 状态栏：文件/段/当前地址。
- 中文/英文 UI 字符串外置（先 en + zh-CN 两份）。

### T10 端到端
- 用一个**本地生成**的测试 PE（MSVC 编一个 hello world，不提交仓库）跑：
  打开 → 看到 entry 反汇编 → 改名 → 加注释 → 存盘 → 关闭 → 重开 → 校验。
- 自动化：`recraft-cli` 层做等价回归（不依赖 UI）。

## 2. 建议执行顺序

1. T0（spike）先跑，结论决定 T9 是否继续用 egui。
2. T2 → T3 → T5 → T4 并行推进（common 先冻结接口）。
3. T6 在 T3/T4/T5 的接口冻结后动工，避免返工。
4. T7 与 T6 后半段并行（IR 只依赖 decode）。
5. T8 先做，作为 T6/T7 的验收工具（UI 之前就能 demo）。
6. T9 最后 6 天集中做，复用 spike 的网格组件。
7. T10/T11 收尾。

## 3. 风险与应对

| 风险 | 应对 |
|---|---|
| PE 解析细节拖时间 | 先支持常见样本；异常结构降级并记录日志，不阻塞 |
| 命令总线/undo 设计返工 | T6 前先用 50 行原型验证"命令 → journal → 回放"闭环 |
| UI 网格从 spike 到产品化超时 | 只产品化反汇编网格；图/Hex 推迟到 M1 |
| L0 伪代码看起来没价值 | 它是 IR 的验收器，不是功能；M1 立即进 L1 |
